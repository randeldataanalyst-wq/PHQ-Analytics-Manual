Overview

The PHQ Analytics system collects project, delivery and collection data for the seven tracked PHQs into one web page. Management can use that page to see what is late, what is unpaid and which region needs follow-up, and to export a branded PDF report.

Who uses it

The Data Analyst maintains it and prepares reports. PHQ heads and management read the dashboard and the PDFs. Purchasing, Warehouse, Sales Admin and Accounting act on the follow-up lists.

What it answers

Which projects are not delivered, partial or overdue; how much is billed, collected and overdue; and which PHQ has the most pending work or the largest unpaid balance.

Where data comes from

Two Project Links 2026 Google Sheets (Jan–Jun and Jul–Sep), plus the Remarks column of the Delivery Monitoring and Collection Monitoring Excel files.

What it never does

It never edits, moves, converts or deletes any source file. Google enforces this with read-only permissions, so even a coding mistake cannot change your sheets.

Tracked PHQs

Quezon, South Cotabato, Region 1, Bicol, Tagkawayan, Cavite and NCR. Rows for any other PHQ (for example Batangas or Region 3, which other PHQs now cover) are left out and listed under Data quality.

The two pages

Dashboard

Live tiles, charts and tables in five sections: A Project fulfillment, B Collection, C Delivery-to-collection, D Regional performance, E Project remarks. Then a Data quality list.

Reports

Choose Delivery, Collection or Overall; set the period, PHQs and sections; preview the pages; download a PDF in IT Avenue's maroon and navy layout.

How it works

Data sources

The script finds columns by their header name, not by column letter. That way the Jan–Jun and Jul–Sep files can have different layouts. Renaming a header the system uses stops that column from being read.

Header row

In each tab the script looks through the first 15 rows for the row containing PROJECT NUMBER (or PR No. in the monitoring files) and treats that row as the header. Blank rows above the header are fine.

Money source

All amounts come from the …FROM OASIS columns, because OASIS is the more reliable record. GROSS SALES and BALANCE without "FROM OASIS" are not used.

Business rules

These rules decide every number on the dashboard and in the PDFs. If a figure looks wrong, check it against this section first.

4.1 Matching project numbers

The same project is typed differently across files. The script reduces every number to a core key: letters, dash, number with PHQ code, dash, two-digit year. Spaces and anything after the year are ignored.

As typedCore key
CORPO- 00021NCR- 26CORPO-00021NCR-26
NHQ- 00251BCL- 26 - SMBNHQ-00251BCL-26
NHQ- 00056NCR- 26 - (W3C)NHQ-00056NCR-26

If the same key appears in both Project Links files, the Jul–Sep row is used and the duplicate is listed under Data quality.

4.2 PHQ names

Spelling and capitals are cleaned up: QUEZON, Quezon and Lucena all become Quezon; REGION 1 and Region I become Region 1; Tagkawayan is the official spelling. Any other value is excluded.

4.3 Reading dates

  • Real date cells are read exactly.
  • Dates typed as text are still read when possible, and listed under Data quality so they can be fixed: 07-Jan-2026, 2026-01-07, 16/03/2026, 06/19/2026.
  • When both numbers are 12 or less (for example 02/01/2026), the date is read day first (2 January) and flagged as ambiguous.
  • A project "delivered before its PO date" usually means day and month were swapped. It is listed, and left out of the average lead time.

4.4 Delivery status

Each project gets exactly one status. The checks run in this order:

Overdue is a flag added on top of Partial or Not delivered. It is not a separate status, so it never double-counts a project.
MeasureRule
Total active projectsRows in Awarded Projects for the 7 PHQs, minus Cancelled / dropped
Fully deliveredActual customer delivery date or received date is filled
Partially deliveredPartial delivery date filled, no final date
Not deliveredNo partial and no final date
Cancelled / droppedNot fully delivered, and the delivery remark contains one of the five keywords
Overdue deliveryPartial or Not delivered, and TARGET CUSTOMER DELIVERY DATE is before today. CUSTOMER'S EXPECTED DATE is used if the target is blank.
Days overdueToday (or the report date) minus the target date
Days late (delivered)Actual delivery date minus target date; zero or less means on time
On-time delivery rateDelivered on or before target ÷ delivered projects that have a target date
Delivery lead timeActual delivery date minus PO date (negative results excluded)

Delivery completionFully delivered ÷ active projects

4.6 Delivery-to-collection and follow-ups

  • Delivered, nothing collected: fully delivered, billed amount above zero, nothing paid.
  • Delivered, payment overdue: fully delivered and an overdue account.
  • Gap (PDF): collection rate minus delivery completion, per PHQ. A large negative gap means the work is done but the money is not in.
  • Follow-up items: overdue deliveries + overdue accounts, per PHQ. Used to rank regions.

"As of" rules in the PDF

A delivery or partial date after the To date is treated as not yet happened. A report for October therefore shows the situation on October 31, even if it is printed later. Money figures are the current OASIS amounts; overdue status and aging are measured against the To date.

Required action (suggested)

Findings and action tracking (automatic)

  • Key findings are written from the numbers: overdue count and the longest delay, partial deliveries, the PHQ with most pending, missing target / PO / DR data, overdue collections and the oldest account, collection rate, the PHQ with the largest overdue balance, payments that need reconciling.
  • Recommendations: the standard list (prioritise longest delays, confirm supplier status, follow up partials, reconcile with OASIS) plus collection items for Collection and Overall reports.
  • Action tracking rows: Delayed items → Purchasing; Incomplete deliveries → Warehouse / Sales Admin; Missing dates / DR numbers → PHQ Admin; Overdue collections → Collections / Accounting; Payments to reconcile → Accounting. Each row has its count and follow-up date.
Preview

The preview draws each PDF page inside the page with pdf.js. Chrome blocks its own PDF viewer inside Apps Script web apps, so the preview cannot use it.

Walkthroughs

Step-by-step guides for the jobs people do most often. Open the one you need.

DailyMorning check of deliveries and collections

For: Data Analyst, PHQ heads · About 5 minutes

  1. Open the dashboard link and wait for "Data read …" to show today's time. Click Refresh data if the sheets were updated after you opened it.
  2. Check the second status line reads Remarks loaded: … delivery, … collection with no red text.
  3. In section A, read Overdue deliveries, then scan Past target delivery date. Rows are sorted by days overdue, so the top rows come first.
  4. In section B, read Overdue balance, then scan Overdue accounts.
  5. In section D, the PHQ scorecard shows which PHQ has the most follow-up items today.
  6. Scroll to Data quality. Send any new issues to the PHQ that owns the row.
MonthlyPrepare the Delivery Monitoring Report for management

For: Data Analyst · About 10 minutes

  1. Click Refresh data so the report uses the latest sheets.
  2. Click Reports at the top.
  3. Select Delivery Monitoring Report.
  4. Click Last month (or set From and To). Leave All projects, status as of the To date selected for a full monitoring view.
  5. Leave All PHQs / Regions ticked, or untick PHQs for a regional version.
  6. Check the sections you need. Keep Supplementary page on if management wants links and full remarks.
  7. Fill in Prepared by (and Noted / Approved by if they will sign). Add a sentence in Additional notes if there is context the numbers do not show.
  8. Click Update preview and read through the pages, especially the Required Action column.
  9. Click Download PDF. The file is named like DMR_20261031.pdf.
MonthlyCollection report for Accounting
  1. Reports → Collection Monitoring Report → set the period.
  2. Set Rows in priority lists to All if Accounting needs every overdue account.
  3. Choose a Follow-up date that matches your collection cycle.
  4. Preview, check the Payments to reconcile row in Action tracking, then Download PDF.
Ad hocFollow up one PHQ's late projects
  1. On the Dashboard, set PHQ to the region, for example Bicol.
  2. Read Past target delivery date and Waiting the longest. The delivery remarks column shows what the PHQ last reported.
  3. Click a project number to open its project sheet for details.
  4. For a printable list: Reports → Delivery → untick every PHQ except that one → Download PDF.
LookupFind a project's remarks
  1. Scroll to E. Project remarks.
  2. Type the PR number, end user or a word from the remark (for example WAITING FOR NOA) in Search.
  3. Use Show to limit to delivery or collection remarks.
  4. If a project you expect is missing, check Data quality → remarks with no matching project. The PR number is probably typed differently in the two files.
DataFix the issues listed under Data quality
  1. Open the Data quality list and expand a group. Each item names the file, tab, row and column.
  2. Dates typed as text: select the column in the source sheet → Format → Number → Date. Re-type any cell that stays left-aligned.
  3. Ambiguous dates: confirm whether 02/01/2026 meant 2 January or 1 February and re-enter it as a real date.
  4. Delivered before PO date: usually day and month swapped. Correct whichever date is wrong.
  5. Unmatched remarks: make the PR number the same in the monitoring file and Project Links.
  6. Back in the dashboard, click Refresh data. Fixed items disappear from the list.
AdminAdd a new Project Links file (for example Oct–Dec)
  1. Open the new Google Sheet and copy its ID from the address bar: the long code between /d/ and /edit.
  2. Check it has Awarded Projects and Project Completion tabs with the same header names.
  3. In Apps Script, open Code.gs and add a line to SOURCES:
    { label: 'Oct–Dec', id: 'PASTE_ID_HERE' }. Put it last, so its rows win if a project appears twice.
  4. Save, run getDashboardData once, then publish a new version (see Setup).
AdminShare the dashboard with the team
  1. In Apps Script: Deploy → Manage deployments → ✏ edit.
  2. Change Who has access from Only myself to Anyone within itavenue.ph.
  3. Keep Execute as: Me. Viewers then see the data without needing access to the source files, and still cannot edit anything.
  4. Click Deploy and share the same web app link.

Setup and deployment

One-time setup of a fresh standalone Apps Script project, and how to publish later changes.

First-time setup

  1. Go to script.google.com → New project. Rename it (for example Data Analytics).
  2. Replace the contents of Code.gs with the provided Code.gs.
  3. + → HTML, name it Index, paste Index.html. + → HTML again, name it Report, paste Report.html. Names are case-sensitive.
  4. ⚙ Project Settings → tick Show "appsscript.json" manifest file in editor. Replace its contents with the provided appsscript.json. Save.
  5. Choose getDashboardData next to ▶ Run and click Run. Approve the permissions. The screen should list only See all your Google Sheets spreadsheets and See and download all your Google Drive files.
  6. Deploy → New deployment → ⚙ Web app. Execute as: Me. Who has access: Only myself to start. Click Deploy and copy the web app URL.
  7. Open the URL. The line under the title should show the current version, for example Dashboard v6 (reports).

Publishing a change

Rule

Saving code does not change the live link. The link runs the code, manifest and permissions from its last published version. After any change, publish a new version.

  1. Edit and save the files.
  2. If appsscript.json changed, run getDashboardData once to approve the new permissions.
  3. Deploy → Manage deployments → select the deployment → ✏ → Version: New version → Deploy. The URL stays the same.
  4. Refresh the web app (Ctrl+F5) and confirm the version label.

To try a change before others see it, use Deploy → Test deployments and open the /dev link.

Permissions and security

The manifest asks Google for two read-only permissions and nothing else, so the source files are protected by Google itself, not only by the code.

PermissionShown to you asWhy it is needed
spreadsheets.readonlySee all your Google Sheets spreadsheetsRead the two Project Links files
drive.readonlySee and download all your Google Drive filesDownload the two Monitoring .xlsx files to read their Remarks
  • Check it any time: myaccount.google.com/permissions → the Apps Script project. If it ever says "edit, create, and delete", the manifest is not in place. Remove access, fix appsscript.json and authorize again.
  • Execute as Me: the page reads data with the owner's access. Viewers do not need access to the source files and get no access to them.
  • Who has access: start with Only myself; widen to Anyone within itavenue.ph to share. Avoid "Anyone" (public).
  • Browser storage: the Reports page remembers your section choices and sign-off names in your own browser only.

Known limitations

  • Payment dates: most rows have no payment date, and one cell cannot record several partial payments. The monthly collections chart and the outstanding-balance trend are therefore approximate. Filling payment dates improves them.
  • Report "as of" money: PDF amounts are current OASIS figures, not a snapshot of the To date. Overdue status and aging do use the To date.
  • Suggested actions come from simple keyword rules and should be reviewed.
  • Remarks files are read from fixed Drive file IDs. A re-uploaded file gets a new ID, which must be updated in REMARK_SOURCES.
  • Ambiguous dates (both parts 12 or less) are read day first.
  • Logo is a small image (227 × 78 px), so it prints slightly soft. A larger PNG can replace it.
  • Speed: each load reads four files; expect a few seconds. Apps Script stops any single run after 6 minutes, far above current needs.
